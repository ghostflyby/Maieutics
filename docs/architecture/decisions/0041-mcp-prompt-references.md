# ADR 0041: MCP Prompt References — the Selection Loop Generalized to Server-Defined Prompts

Status: Draft

Date: 2026-10-08

Related: ADR 0026 (resource plane, `mcp://` escape hatch), ADR 0039 (skill
discovery and selection), ADR 0032 (content-path stance), ADR 0040
(contribution framework — why prompts are NOT a kind),
`docs/mcp-prompt-interaction-design.md` (full design),
`docs/web-frontend-protocol.md` ("Skill references")

## Context

The kernel consumes two of MCP's three product-facing primitives: tools
(invoked by the model) and resources (read through the resource plane). The
third — prompts — is absent: server-defined, user-invoked templates that
expand into conversation content. The skill selection loop (ADR 0039
interaction half) established the pattern for exactly this shape of
interaction: catalog endpoint → markdown-link reference in turn text →
build-time expansion with typed failures → editor boundary model. Prompts
are the same interaction with three real differences: identity is
server-scoped (not a global flat namespace), templates are parameterized,
and content is generated by a server round-trip at expansion time.

## Decision

1. **Prompts join the session view as a consumer face of the MCP adapter,
   not a contribution kind.** They ride server generations (discovery-time
   `prompts/list` beside tools/resources, `ListChanged`-driven relist) and
   the existing lease path. No manifest surface, no fingerprint domain, no
   reconcile pass — ADR 0040's framework is untouched.

2. **The reference grammar is a markdown link over a dedicated scheme:**
   `[text](mcp-prompt://<serverId>/<promptName>)`, arguments as URL query.
   `mcp-prompt://` is a reserved built-in scheme (both reserved-scheme
   tables). Prompt names outside the reference charset stay listed but
   `referencable: false` — the grammar stays strict, near-misses degrade.

3. **Expansion is build-time, lease-guarded, budgeted.** The turn build
   resolves the server's lease (typed `mcp_prompt_unavailable` while
   retired/reconnecting), calls `prompts/get` under the server's
   `RequestTimeout`, validates arguments against the declared set
   (missing required or extraneous → `mcp_prompt_argument_invalid`,
   fail-closed), and appends the result as framed user-side content after
   skill parts. One shared per-turn reference-content budget (8 MiB, the
   skill budget generalized) covers skill bodies and prompt expansions
   together; a single prompt's expansion is capped at 4 MiB. Failures fail
   the submission, never truncate.

4. **Prompt messages are injected as user-side framed content with role
   labels, not as conversation turns.** `GetPromptResult.Messages` bridge
   via the SDK's `ToChatMessages()` and then flatten to `TextContent`
   parts with a `[role]` header per message. Rationale: the content enters
   through the user's selection (the highest-trust channel inside a turn),
   the authoritative transcript must not gain assistant turns that never
   happened, and role labels preserve the template's guidance structure
   for the model. This is a recorded decision with a named revision
   trigger: if experience shows models need genuine role separation, the
   injection can be revisited — the wire shape does not preclude it.

5. **The editor interaction reuses the skill boundary model unchanged.**
   The model parameterizes over the URI scheme; minting, position sync,
   mention escaping, and submit encoding are the same machinery. Stages:
   (1) kernel + protocol doc; (2) frontend catalog completion and
   no-argument insertion; (3) input-request form for required arguments —
   the existing elicitation machinery, not a new form channel.

## Consequences

- The selection loop pattern (catalog → link reference → build-time
  expansion → typed errors) is now instantiated twice; the third
  instance, if any, starts from this design's §1 table rather than from
  scratch.
- Embedded resource blocks inside prompt messages are ignored with a
  diagnostic in stage 1 (no second-level expansion); the objects://
  ingestion path is the evaluated follow-up.
- `GET /v1/prompts` lists prompts of reconnecting servers with
  `state: "reconnecting"` — visible but selecting one answers typed
  `mcp_prompt_unavailable`, mirroring resource reads.
- The `skill_budget_exceeded` error becomes the shared reference-content
  budget failure; its name is kept for wire compatibility and its
  documentation broadened.
- serverId embeds `:` (the `plugin:<id>::<module>` form); it is a legal
   reg-name URI host, and both sides' grammars match on the literal
   `mcp-prompt://` prefix rather than a generic URI parser.
